# 過去問・誘導ステップの追加手順

この資料は、正答や数式を壊さずに収録内容を増やすための手順です。

## 1. 先に確認するもの

- 公式問題
- 公式解答例
- 年度、科目、大問番号
- 各小問の配点と部分点
- 問題・解答画像を利用できる範囲

正答と途中式は、生成AIの知識だけで確定しないでください。必ず公式資料と独立計算を照合します。

## 2. 既存問題の修正

問題に関する情報は3か所に分かれています。

- 試験セット共通: `app/exam/2025-q2.ts` の `QUESTION_META`（論点名、出題形式、正答、公式配点、部分点、問題・解答画像、PAR）
- 通常版固有: `app/page.tsx` の `QUESTIONS`（レイド用タイトル、`axis`、`options`）
- 誘導版固有: `app/guided/data.ts` の `GUIDED_QUESTIONS`（`goal`、`steps`、`finalAnswer`）

正答、公式配点、画像パス、PARを変える場合は `app/exam/2025-q2.ts` だけを直します。同じ値を各モードへ書き戻さないでください。変更後は `npm run test:data` で、誘導版の `finalAnswer` と通常版の正答が食い違っていないかを確認します。

正答は文字列配列です。

```ts
correct: ["C"]          // 単一選択
correct: ["C", "H"]    // ①C、②H
correct: ["A", "C", "D"] // 複数選択
```

誘導版の各ステップの正答は0始まりの選択肢インデックスです。

```ts
choices: [
  { label: "誤答" }, // 0
  { label: "正答" }, // 1
  { label: "誤答" }, // 2
],
correct: 1,
```

選択肢の並べ替え時に `correct` を更新し忘れないでください。

## 3. 画像の追加

現在の命名規則:

```text
public/exam/<year>-q<major>/q<minor>.webp
public/exam/<year>-q<major>/s<minor>.webp
```

例:

```text
public/exam/2025-q2/q1.webp
public/exam/2025-q2/s1.webp
public/exam/2025-q2/s2b.webp
```

解答が複数画像なら `solutions` に読む順で並べます。

```ts
solutions: [
  "/exam/2025-q2/s2.webp",
  "/exam/2025-q2/s2b.webp",
],
```

画像確認:

- 文字と添字がスマートフォンで判別できる
- 拡大モーダルで原寸相当を読める
- 問題番号と解答番号が一致する
- 余白の切り落としで条件文が欠けていない
- 向きとページ順が正しい

## 4. 通常版の問題定義

通常版の `Question` は、共通メタデータ `QuestionMeta` に通常版固有の3項目を足したものです。

`app/exam/2025-q2.ts` の `QuestionMeta`:

| 項目 | 意味 |
|---|---|
| `id` | 1始まりの連続した小問番号 |
| `topic` | 結果・復習一覧に出す論点名 |
| `mode` | `single`、`dual`、`multi` |
| `correct` | 正答文字列の配列 |
| `points` | 公式配点 |
| `partial` | 解答欄ごとに配点が分かれる場合の内訳。問2は ①C=3点、②H=4点 |
| `image` | 公式問題画像 |
| `solutions` | 公式解答画像の配列 |
| `par` | 目標秒数 |

`app/page.tsx` の `QUESTIONS` で足すもの:

| 項目 | 意味 |
|---|---|
| `title` | レイド用の短い問題タイトル |
| `axis` | 任意ヒントとして出す解法の軸 |
| `options` | 解答欄に表示する文字 |

現在の実装には `QUESTIONS[attempt.id - 1]` という参照があります。`id` を飛び番にしたり、配列順とずらしたりしないでください。`npm run test:data` がこの前提を検証します。

通常版の採点関数 `officialPoints`（`app/scoring.ts`）は、`points` と `partial` だけを見て得点を出します。選択肢の文字や点数を採点コードへ直接書かないでください。配点を変えるときは `app/exam/2025-q2.ts` だけを直し、`npm run test:unit` で採点結果を確認します。

`axis` は解法そのものを全部書かず、「何へ変換するか」「どの定義へ戻るか」までに留めます。

## 5. 誘導問題の設計

### 5.1 まず解法を一本道にする

公式解答をそのまま細切れにするのではなく、自力で到達するために必要な判断点を並べます。

代表的な順序:

```text
条件を読む → モデルを選ぶ → 式を立てる → 変形する → 数値計算 → 最終選択肢
```

1問4〜6ステップを目安にします。単なる四則計算だけの段を増やしすぎないでください。

### 5.2 1ステップ1判断

良い問い:

> 60歳以降では、60歳まで生存する確率と条件付生存確率をどう接続する？

避ける問い:

> 生存関数を求め、積分し、平均寿命を使ってαを求めよ。

後者は複数の判断が一段に混ざっています。

### 5.3 誤答選択肢

典型的な誤りから作ります。

- 符号の反転
- 分子と分母の逆転
- 期始・期末の取り違え
- 添字や境界年齢の取り違え
- `D`、`N`、`M` 基数の混同
- 比の向きの逆転
- 重複除去の忘れ

明らかにふざけた選択肢や、単位だけ異なる選択肢で水増ししないでください。

### 5.4 `wrongHint`

- 正答の式をそのまま書かない
- 一度に一つの確認点だけ示す
- 「もう一度考えよう」だけで終わらせない
- 典型的誤解と対応させる

### 5.5 `explanation`

- その段が正しい理由を1〜3文で説明
- 次段の結論を先に明かさない
- 記号の意味と式変形を省略しすぎない
- 公式解答と異なる記法を使うなら対応関係を示す

### 5.6 最終整合性

各問題について確認します。

- 最後のステップから `finalAnswer` が導ける
- `finalAnswer` が通常版の `correct` と一致する
- すべての `step.correct` が `choices` の範囲内
- `choices` の `label` が同一ステップ内で重複していない
- 問題画像と解答画像のパスが存在する
- ステップ数表示と実数が一致する

## 6. 新しい年度・大問を追加する場合

現在の画面は「2025年度 問題2」「8問」「56点」を前提とした表示と採点が複数あります。新しい年度の問題を既存配列へ単純に追記しないでください。

先に次をデータ化する改修が必要です。

- 試験セットID
- 年度、科目、大問番号
- 問題数
- 合計配点
- 目標時間
- 出典表示
- 問題配列
- 保存データを試験セット別に分けるキー

推奨する方向は、通常版と誘導版が共通の試験セットメタデータを参照し、各モード固有の情報だけを分離することです。ただし、現在の8問を壊さないテストを先に追加してからリファクタリングしてください。

保存形式を試験セット対応へ変える場合、既存3キーのデータを2025年度問題2として移行できるようにします。

## 7. 変更後の確認

```bash
npm run lint
npm run build
```

さらに対象問題を実際に操作します。

通常版:

- 正答、誤答、部分点
- 公式解答画像
- メモ保存
- 次問題への遷移

誘導版:

- 各ステップで一度は誤答し、ヒントを確認
- 正答後の説明
- 最終解答
- 公式解答画像
- クリア進捗の再読込後復元
