# CLAUDE.md

## このプロジェクトの目的

ACTUARY QUESTは、アクチュアリー試験「生保数理」の実際の過去問を、スマートフォンで反復するための学習Webアプリです。

単なる四択クイズではありません。難しい問題を自力で攻略する感覚と、学習を継続したくなる報酬感を両立させます。

作業開始時は、次の順で読んでください。

1. `README.md`
2. `docs/PRODUCT_SPEC.md`
3. 問題追加なら `docs/ADDING_EXAM_CONTENT.md`
4. 変更対象のコード

## 絶対に守る仕様

1. 通常版 `/` と誘導版 `/guided` を別モードとして維持する。
2. 過去問の問題文、数式、選択肢、正答、公式配点を、UI改善の都合で変更しない。
3. 誘導版でも元の問題を簡単な別問題へ置換しない。考える順番だけを分解する。
4. 誘導版の誤答時は正解を即表示しない。次に確認すべき一点だけを示し、再選択させる。
5. 正解や誘導内容を変更するときは、公式問題・解答画像と計算を照合する。モデルの記憶だけで決めない。
6. 通常版のメモ、成績、誘導版の進捗を消さない。保存形式の変更には後方互換または移行処理を付ける。
7. モバイルファースト、日本語中心、片手操作可能なタップ領域を維持する。
8. 依頼のない全面リライト、フレームワーク移行、依存追加をしない。
9. `.openai/hosting.json`、`package-lock.json`、`scripts/`、`build/`、`worker/`を削除・置換しない。
10. 公式問題・解答画像を生成画像や書き起こしだけに置換しない。

## 現在の構成

| 場所 | 責務 |
|---|---|
| `app/exam/2025-q2.ts` | 試験セット共通のメタデータ。論点名、出題形式、正答、公式配点、部分点、問題・解答画像、PAR |
| `app/scoring.ts` | 公式得点の計算。配点・部分点はメタデータから取る |
| `app/storage.ts` | 端末内保存の読み書き。キー定義、型検証、保存失敗の検知 |
| `app/page.tsx` | 通常版。レイド用タイトルと解法の軸、採点、スコア、メモ、端末保存、全画面状態 |
| `app/globals.css` | 通常版と共通のグローバルスタイル |
| `app/guided/page.tsx` | 誘導版。マップ、ステップ進行、フィードバック、完了保存 |
| `app/guided/data.ts` | 誘導版8問・37ステップの型とデータ |
| `app/guided/guided.module.css` | 誘導版専用スタイル |
| `public/exam/2025-q2/` | 公式問題 `q*.webp` と公式解答 `s*.webp` |
| `app/layout.tsx` | メタデータ、モバイルviewport、全体レイアウト |
| `tests/exam-data.test.mjs` | 試験データの整合性テスト（依存不要） |
| `tests/storage.test.mjs` | 端末内保存の読み書きテスト（依存不要） |
| `tests/scoring.test.mjs` | 公式得点の計算テスト（依存不要） |
| `tests/rendered-html.test.mjs` | ビルド成果物がHTMLを返すことの最小テスト |
| `.openai/hosting.json` | OpenAI Sitesの識別・バインディング情報 |

論点名、正答、公式配点、問題・解答画像、PARは `app/exam/2025-q2.ts` が唯一の出所です。通常版と誘導版はここから読み取るので、これらを2か所に書かないでください。各モードに残すのは、通常版のレイド用タイトル・`axis`・`options` と、誘導版の `goal`・`steps`・`finalAnswer` だけです。

## 端末保存の契約

| キー | 内容 | 現在の形式 |
|---|---|---|
| `actuary-raid-progress-v2` | 通常版の最高点、クリア数、連続学習日数 | JSON object |
| `actuary-raid-stuck-notes-v1` | 問題番号ごとの詰まりメモ | JSON object `{ "1": "..." }` |
| `actuary-guided-progress-v1` | 誘導版でクリア済みの問題ID | JSON array of numbers |

キー名を変更しないでください。やむを得ず形式を変える場合は、旧キーを読み、新形式へ一度だけ移行できる実装とテストを追加してください。

読み書きは `app/storage.ts` に集約しています。`localStorage` を各コンポーネントから直接触らないでください。読み込み時に型を検証し、壊れた値でも画面が落ちないようにしています。保存に失敗した場合は握り潰さず警告を出します。

現時点ではバックエンド、認証、外部APIはありません。`localStorage` は端末内の学習状態にだけ使用しています。

## 数学・アクチュアリー内容を変更する手順

1. 対象の公式問題画像と公式解答画像を読む。
2. 正答、途中式、添字、支払時点、端点、単位を独立に検算する。
3. 通常版の `correct` と誘導版の `finalAnswer`・各 `step.correct` が一致することを確認する。
4. 誤答選択肢が無意味なダミーではなく、典型的な誤解に対応しているか確認する。
5. `wrongHint` は答えを言わず、確認対象を一つに絞る。
6. `explanation` はその段の論理だけを説明し、未到達の後続結論を先取りしない。

数式の文字列では、既存のUnicode添字・上付き文字・二見記法との一貫性を優先します。見た目だけのために意味の異なる記号へ置換しないでください。

## 実装方針

- 既存のReact関数コンポーネントとTypeScriptの型を使う。
- 小規模なUI状態は現在の `useState` / `useMemo` / `useEffect` で十分。新しい状態管理ライブラリを入れない。
- 通常版はグローバルCSS、誘導版はCSS Modulesという現在の境界を維持する。
- 画像は `next/image` へ機械的に移行しない。公式問題の原寸拡大とスクロール挙動を先に検証する。
- タップ可能要素には意味のあるラベルを付け、キーボードのEscapeでモーダルを閉じられる状態を保つ。
- 効果音・振動は追加報酬であり、動作不能の原因にしない。
- 変更範囲外の見た目、文言、採点ロジックをついでに変更しない。

## 作業フロー

1. `git status --short` で既存変更を確認する。
2. 関連ファイルを読み、変更前に短い実装方針を示す。
3. 最小範囲で実装する。
4. `npm run lint` を通す。
5. `npm run build` を通す。
6. UI変更時は、通常版と誘導版の両方をモバイル幅で操作確認する。
7. 最後に、変更内容、確認結果、未解決事項を簡潔に報告する。

`npm test` はビルドも実行するため、リリース前またはビルド出力に関わる変更で使用してください。

## UI変更の最低確認項目

- `/` のロビーから通常演習を開始できる。
- 単一選択、2欄選択、複数選択が正しく採点される。
- 解答後に公式解答を開閉できる。
- 詰まりメモを保存・削除でき、再読込後に復元される。
- `/guided` のマップから任意問題を開始できる。
- 誤答でヒントが出て、同じステップを再挑戦できる。
- 正答後に次のステップへ進み、最終的にクリアできる。
- 誘導版の完了状況が再読込後に復元される。
- 長い数式が画面全体の横スクロールを発生させない。
- 問題・公式解答のモーダルを閉じられる。
- 360px前後の画面幅で主要ボタンが押せる。

## 完了条件

- ユーザーが依頼した体験が実際に操作できる。
- 既存2モード、採点、保存、公式画像表示が壊れていない。
- 数学的内容を変更した場合、照合根拠を説明できる。
- lintとproduction buildが成功する。
- 意図しないファイルや生成物をコミットしない。

## デプロイ

このリポジトリはOpenAI Sites向けの構成を含みます。Claude Code単体ではSitesへの公開操作を前提にしません。

Claude Codeではソース変更とローカル検証まで行い、公開はSitesを操作できるCodexへ戻すか、ユーザーが明示した別のホスティング先へ設定してください。依頼なしにVercel等へ移行しないでください。
